# Integrated engine mapping method

This study uses integrated HEAD `32f9d3f8a71dc0d2a5f18520bfad738e67ba26c0`. The CLI checks HEAD before any corpus enumeration, and records source hashes and the canonical input hash. The module is research-only; it does not change any production component. The script is [engine-map.ts](../../../scripts/web-voicing-corpus-v2/engine-map.ts).

## Input and observation boundaries

The exported `NormalizedVoicingRow` retains the original source row and provenance extensions. Required fields are `rowId`, `sourceId`, `lineageId`, `rawLabel`, `statesHighToLow`, `tuningMidiHighToLow`, `capoFret`, `orientationConfidence` and `labelConfidence`. Optional reviewed normalization supplies `chordId`, `rootPitchClass`, `slashBassPitchClass` and a declared `context`. Null state/tuning arrays and ambiguous confidence remain inventory exclusions. The six physical strings run high E to low E, with standard tuning `[64,59,55,50,45,40]`, `-1` unplayed, `0` open, and positive absolute frets. This follows the integrated [type contract](../../../src/domain/chord/engine/types.ts) and [request compiler](../../../src/domain/chord/engine/requestPolicy.ts).

The primary scope is uncapoed, standard-tuning six-string allocations at frets 0–15. Unknown capo, nonzero capo, nonstandard or unresolved tuning, frets above 15, ambiguous orientation and ambiguous chord labels are excluded with explicit reasons. A source fret-position offset must have been resolved upstream before this boundary. Exclusion means outside the comparable default study domain; it does not mean an invalid or undesirable voicing.

`parseChordLabel` accepts a narrow note-name/suffix/slash grammar using exact [registry](../../../src/domain/chord/registry.ts) symbols and aliases plus enumerated spelling aliases. Case is retained: `CM7` and `Cm7` differ. Unsupported qualities such as `add9` are not silently reduced. A reviewed explicit chord ID/root can describe a source-specific notation that the grammar does not parse; if the grammar does parse and conflicts with supplied normalization, the row is excluded. The compiler checks slash-bass support. The default context is standalone; accompaniment is used only when explicitly declared. Missing root tones are never grounds to infer accompaniment.

An exact allocation key contains the entire state tuple under the fixed tuning/capo domain. Query identity contains chord quality, root, context and any slash obligation. `shapeFamilyKey` keeps all open allocations exact; for closed allocations it subtracts the minimum stopped fret while retaining string and mute positions. The evaluator must combine this physical family with tuning and chord quality, as specified in the [fixed evaluation protocol](evaluation-protocol.md). Family membership is a withholding/description device, not a preference label.

## Authoritative enumeration and controls

For each unique query, `buildIntegratedUniverse` constructs [EngineSession](../../../src/domain/chord/engine/session.ts), calls `begin({},18)`, runs `step()` until complete and calls `finish()`. The empty view has no filter or similarity request. Session itself compiles intent, uses the authoritative [StructuralIterator](../../../src/domain/chord/engine/structuralGenerator.ts), applies [physical-screen-v1](../../../src/domain/chord/engine/physical.ts) and projects/scorers [classic features](../../../src/domain/chord/engine/classicFeatures.ts) with [classic-v1](../../../src/domain/chord/engine/deterministicRanking.ts). No legacy exploration generator is imported or called.

The mapper asserts exact completion; structural = PASS + UNCERTAIN + REJECT; REJECT = 0 for this frozen capability; survivors = structural; complete packed storage; packed count = survivor count; and uniqueness of every allocation. Every [packed store](../../../src/domain/chord/engine/packedStore.ts) survivor is copied once and sorted using the production `compareRank`: descending integer score numerator, then ascending physical-string numeric tuple. The first 18 of this independently sorted complete pool must equal the session's authoritative top 18. The denominator is 110000; physical status is never a ranking term.

The complete candidate universe is shared among all source rows for the same query. Each target must match the exact physical tuple. An absent target receives diagnostics for extra/non-formula pitches, missing required tones, insufficient distinct pitch classes and slash-bass mismatch as applicable, followed by the authoritative structural lookup rejection. Labels are not rewritten to fit observed pitches. The exact membership failure remains distinct from preprocessing exclusions; the evaluator decides its retrieval denominator using the frozen protocol.

The CLI caches each complete ranked universe under `mapping/universes/<query-hash>.json`, with ordered columns `[statesHighToLow, scoreNumerator, physicalStatus]`. Summary metadata links each cache path and hash. No empirical pruning is allowed. The API also exposes on-demand full candidate description to avoid retaining rich objects for millions of allocations. Consumers should process and dispose one universe at a time. No training or corpus evaluation runs on module import.

## Features and physical interpretation

Target descriptions include actual integrated [factual descriptors](../../../src/domain/chord/engine/facts.ts), classic feature scalars, exact rank/score, optional 14-term ledger and production physical assessment metadata. Recomputed feature score and physical status must equal the stored values. Required factual slices include root presence, bass/top tones, density, open/closed, omissions, contiguous strings, quality, context and status. High stopped position means minimum stopped fret at least 11; low means maximum stopped fret at most 7; all-open and other positions remain explicit.

Optional Physical Envelope v2 covariates call the existing research-only [geometry/contact implementation](../../../scripts/physical-envelope-v2/features.ts) and primary `acoustic_gs_mini_reference_v2` [instrument profile](../physical-envelope-v2/instrument-profiles.json). They expose full-cell longitudinal gap, transverse and planar lower bounds, wire span, selected midpoint diameter and operation/contact topology. The primary descriptive instrument differs from production's default 647.7 mm span profile; both profile identities remain explicit. These are geometric model quantities, not calibrated human difficulty, comfort, playability or probabilities. Contact partition groups are not verified finger counts. Production `humanValidation` remains `absent`.

The descriptive expanded-versus-legacy flag duplicates the offline predicate definitions used by the integrated census: old required-tone policy, monotonic pitch by physical-string traversal and the archived [old hand-policy function](../../../src/domain/chord/fretGeometry.ts). It does not call the old generator and does not remove or rerank a survivor. For the default standalone/accompaniment requests this reproduces the old allocation gates; slash-constrained cases use the same old-gate intersection within their explicit integrated query and are not claimed to recreate a historical slash UI universe. Old hand-policy rejection is never described as human impossibility.

## Verification and invocation

The isolated strict TypeScript check passes. [verify-mapping.ts](../../../scripts/web-voicing-corpus-v2/verify-mapping.ts) checks case-sensitive aliases, unsupported quality, slash spelling, ambiguous labels, null state arrays, capo/fret exclusions, normalization conflict, open-exact/closed-relative family identity, exact target lookup and ledger score identity. The synthetic C-major standalone control produced 13,331 integrated survivors: 992 PASS and 12,339 UNCERTAIN. The open C allocation `[0,1,0,2,3,-1]` has classic rank 8. This is a mapping implementation control, not web evidence or a corpus evaluation.

Run from the project root:

```powershell
node_modules/.bin/tsx.cmd scripts/web-voicing-corpus-v2/verify-mapping.ts
node_modules/.bin/tsx.cmd scripts/web-voicing-corpus-v2/engine-map.ts canonical.json .research/web-voicing-corpus-v2/mapping
```

`canonical.json` can be a row array or an object with `rows`. The CLI writes `summary.json`, `rows.jsonl` and complete ordered universe caches. Every input row appears once in `rows.jsonl`, including all exclusions and original provenance. Broad numeric features exported by the module are available for auditing; their presence does not authorize changing the fixed evaluator feature set or fitting after observing outcomes.

The [notation correction ledger](notation-corrections.json) records one pre-evaluation parser omission: the source-explicit spelling `Maj7` is now accepted as registry `major-7`. Raw labels are unchanged; the three affected authored rows are listed. The prior parser is retained as a hash-verified snapshot for the reference mapping, whose labels contain no `Maj7` and whose results are unaffected. The first curated mapping is retained; `curated-mapping-v2` is the final corrected mapping.

Full serialized-artifact verification additionally runs [verify-mapping-artifacts.mjs](../../../scripts/web-voicing-corpus-v2/verify-mapping-artifacts.mjs). The reference diagnostic preserves all 7,070 source rows, maps 1,691, and verifies complete orders/status partitions for 6,417,643 survivors over 349 queries, including 240 default queries exactly matching the historical integrated census. The final curated mapping preserves all 51 source rows, maps 47, retains four intended ambiguous-label exclusions, and verifies 999,184 survivors over 39 queries; all 39 match the integrated census. Cache hashes, target rank/tuple/score/status and original-row identity/order all pass. Each mapping directory contains its machine-readable `verification.json`.
