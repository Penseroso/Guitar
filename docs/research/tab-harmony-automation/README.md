# TAB 자동 화성 분석 연구

**판정은 제품 통합 NO-GO, 제공 코드 기반 국소 조성 후보 연구 GO다.** 전문가 코드 구간을 제공하자 국소 조성의 시간 가중 정확도가 42.9%에서 77.3%로 올랐다. 반면 한 성부만 주었을 때 자동 화성 구간화는 고정 마디 기준선을 넘지 못했다. 전조에 가까운 변화만 골라도 공동 추정은 제안 54건 중 29건이 주석 기반 대리 지표와 일치하지 않았다.

제품 기준은 `8079768`이다. 실험은 [후속 구현 계획](../../implementation/tab-harmonic-progression-plan.md)의 3단계를 오프라인에서 수행했다.

## 데이터와 평가

[Annotated Beethoven Corpus](https://github.com/DCMLab/ABC/tree/b6b7d38500bacb30c81db7e09d8790df1a2edd46)의 사중주 16곡에서 첫 악장을 하나씩 골랐다. 작곡 작품 단위로 개발 5곡, 보정 4곡, 평가 7곡을 분리했다. 보정 파일에는 실행 소스와 설정의 해시가 들어 있다. 평가 원문은 이 파일을 만든 뒤 가져왔다. 평가에는 전체 악보와 같은 악장의 제1바이올린 성부만 남긴 입력을 각각 사용했다. 단일 성부 실험에도 악보의 마디 경계를 입력으로 제공했다. 이 성부는 반주 정보 제거에 대한 민감도 검사이며, 별도 기타 TAB 검증 자료의 역할은 실제 TAB 주석이 맡아야 한다. [분할·원문 해시](source-manifest.json) · [보정 고정 파일](locked-config.json).

악보 순서에서 모든 엔딩을 한 번씩 포함했다. 마디의 실제 표기 길이와 마디 내 오프셋으로 정확한 분수 좌표를 계산하고, ABC의 `quarterbeats_all_endings`가 있는 행은 일치 여부를 검사했다. `duration`은 분수로 계산하고, 장식음은 제외했다. 관찰 피치 클래스가 표기 구간에 포함되는 시간을 가중치로 사용했다. 같은 피치 클래스의 옥타브 중복을 두 번 세지 않았다. 음표 머리의 시작과 끝, 마디 시작을 추정 경계의 후보로 사용했다. 대안 마디 및 타이의 연주 재현은 실험에 포함되지 않는다.

ABC 근음은 국소 으뜸음 기준 5도 좌표다. 국소 키는 장조에서는 장음계, 단조에서는 자연단음계 기준으로 변환했다. THE MODUS의 표시용 Roman 규약을 이 입력에 적용하면 단조의 III·VI·VII가 달라질 수 있다. ABC의 모드 필드와 변환 결과가 일치하는지 검사했다. 평가 7곡은 코드 주석 3,674개, 비교 대상 코드 변화 경계 2,993개를 포함한다. 근음+품질의 시간 평가에서는 지원한 품질 6,592 사분음표를 대상으로 삼았다. 증6화음 등 실험 사전에 없는 품질의 주석 31개는 품질 점수에서 제외하고 근음 및 경계 점수에는 반영할 수 있다. [좌표·화성 변환 근거](https://github.com/johentsch/ms3/blob/fcc1909fa933f07a8e0bdc8c9ab0e688507439d5/src/ms3/utils/functions.py#L4077) · [악장별 입력·결과](heldout.json).

## 실험 결과

| 실험 | 전체 악보 | 제1바이올린만 |
| --- | ---: | ---: |
| 음분포만 → 국소 조성 정확도 | 42.9% | 23.6% |
| 전문가 코드 구간 제공 → 국소 조성 정확도 | **77.3%** | **72.7%** |
| 고정 마디 → 코드 변화 경계 F1 / 근음+품질 정확도 | .558 / 38.5% | **.533** / 17.4% |
| 피치 클래스 변화 → 경계 F1 / 근음+품질 정확도 | .448 / 45.9% | .441 / 11.8% |
| 전문가 국소 조성 제공 → 구간 DP의 경계 F1 / 근음+품질 정확도 | **.632 / 52.0%** | .485 / **22.5%** |
| 코드 구간부터 추정 후 조성 → 경계 F1 / 화음 정확도 / 조성 정확도 | .625 / 45.1% / 74.6% | .484 / 14.2% / 57.4% |
| 구간·화음·조성 공동 추정 → 경계 F1 / 화음 정확도 / 조성 정확도 | .614 / 50.7% / 75.3% | .477 / 19.8% / 50.8% |

- **전문가 코드 구간 → 조성.** 음분포에 코드 기능의 단서와 전환 비용을 추가했다. 전체 악보에서 보정 기준을 적용하자 발행 범위 57.1%, 발행한 결과의 정확도 80.5%로 사전 조건을 충족했다. 제1바이올린에서는 50.7% / 76.0%였다. 전체 악보에서도 악장별 강제 예측 성능은 43.4–89.9%였다.
- **전문가 조성 → 구간.** 정답 키는 각 후보 구간의 시작에서 코드 점수에만 반영했다. 정답 경계 자체를 후보에 삽입하지 않았다. 전체 악보에서 마디 기준선 대비 F1이 .074 올랐고, 제1바이올린에서는 .047 내려갔다. 실험의 양쪽 개선 조건을 충족하지 못했다.
- **공동 추정.** 순차 추정보다 다성 입력에서 화음 정확도가 좋아졌지만 경계 F1은 떨어졌다. 제1바이올린에서는 코드·키 모두 보정 악장에서 목표 정밀도를 달성할 수 있는 발행 임계값을 찾지 못했다. 실험은 점수 마진을 사용하며 확률로 보정한 수치를 제시하지 않는다.
- **시간 없이 포지션 순서만 남긴 검사.** 제1바이올린 포지션 최대 25개의 음 개수로 키 프로파일을 계산했다. 8,506개 중 2,772개 포지션(32.6%)이 전문가 키와 일치했다. 시간 모드는 사분음표 길이로, 이 실험은 포지션 개수로 채점했고 윈도 정의도 다르다.

경계는 ±½ 사분음표에서 일대일로 대응시켰다. 같은 근음과 품질을 공유한 인접 구간의 내부 분할은 경계 점수에서 합쳤다. 원래 분할 수를 별도로 기록했다. 전체 악보에서 PC 변화 기준은 경계 9,810개를 제안해 정답 2,993개의 95.7%를 찾았고 정밀도는 29.2%였다. 공동 DP는 제안 1,790개와 재현율 49.0%를 기록했다. [평가 계약](protocol.json) · [개발 결과](development.json) · [보정 결과](calibration.json) · [평가 결과](heldout.json).

## 토닉화와 국소 조성 변화

| 전체 악보 | 비교 이벤트 | 일치 / 제안 / 기준 | 정밀도 / 재현율 |
| --- | --- | ---: | ---: |
| 코드 구간 제공 → 조성 | 주석의 국소 키 변화 | 39 / 110 / 93 | 35.5% / 41.9% |
| 코드 구간 제공 → 조성 | 적용 도미넌트 도착 | 137 / 215 / 199 | 63.7% / 68.8% |
| 공동 추정 | 적용 도미넌트 도착 | 33 / 64 / 199 | 51.6% / 16.6% |
| 공동 추정 | 지속과 도미넌트 해소를 요구한 변화 | 25 / 54 / 80 | 46.3% / 31.3% |

적용 도미넌트는 동일한 국소 키 안의 별도 목표 도착으로 비교했다. 기준은 ABC의 적용근 주석과 실제 V(7)→장·단화음 도착을 함께 요구한다. 국소 키 변화는 같은 도착 키에 대해 ±4 사분음표에서 비교했다. 마지막 행의 기준 80건은 ABC의 국소 키 표기에 **8 사분음표 이상 지속, 세 코드 구간 이상, 구간 안 V(7)→으뜸화음**을 추가로 적용한 대리 지표다. 주석과 추정값에 동일한 필터를 적용했다. 실제 전조 정확도를 판단하려면 합의된 전조 주석이 추가로 필요하다.

별도로 만든 반례에서는 C6과 Am7의 관찰 피치 클래스가 같아서 가능한 화성 경계 하나가 아예 입력에 드러나지 않았다. C 아르페지오는 PC 변화 경계 다섯 개를 만들었지만 DP는 하나의 코드 구간을 유지했다. 동일한 A7→Dm 앞부분을 가진 두 진행은 이후 C로 돌아가는 경우와 D단조 근거가 계속 쌓이는 경우에 다른 결과를 냈다. 또 한 선율에 두 반주가 들어맞고, C장조와 D도리안이 같은 음집합을 공유하는 경우를 검증했다. [반례와 스트레스 결과](controls.json).

제품 API를 직접 호출한 검사에서는 결측이 있는 스냅샷에서도 특정 시점은 완전할 수 있었다. 이번 전체 악장 시간 실험은 시간 증거가 완전한 입력에 한정했다. C6과 Am7은 기존 제품 인식기에서 모두 정확한 후보로 남았다. [제품 API 검사](product-controls.json).

## 다음 판단과 재현

1. **제공 코드에서 국소 조성 후보 연구 GO.** 확인 가치가 가장 컸다. 다음 데이터는 사용자가 제공한 코드와 독립 주석이 있는 실제 기타 예제로 구성하고, 모드·전조·모호성에 대한 주석자 합의와 다중 정답을 포함한다.
2. **자동 구간화 연구 유지.** 마디 기준선을 보존하고, 실제 TAB에서 근음 없는 보이싱·코드가 미정인 구간·반주 없는 단선율을 따로 평가한다. 코드 이름을 하나로 줄이기 전 후보 집합 자체에 정답이 들어 있는지 측정한다.
3. **자동 화음·국소 조성·전조 제품 적용 NO-GO.** 입력이 약해질 때 정확도와 발행 범위가 떨어졌고 키 변화 오탐이 남았다. 다음 실험에서 작품 단위 검증과 기타 사용자 과업을 함께 통과해야 한다.

공동 추정은 한 악장의 전체 악보에서 약 1.04–1.92초였다. 1,024 포지션·6,144개 음표를 사용한 합성 스트레스는 약 0.92초, 프로세스 최고 RSS 약 34MB였다. 측정은 Linux x86-64 호스트의 Python/NumPy 오프라인 실행이며 장치 지연과 취소 응답은 후속 통합 실험의 대상이다. 평가를 한 번 더 실행해 경과 시간 외의 결과가 모두 동일함을 확인했다. [실행 결과](heldout.json) · [스트레스 조건](controls.json) · [재현 검증](verification.json).

THE MODUS 코드에서 11개 공식과 기존 인식기의 반례를 내보냈다. Python에서는 해당 공식에 점수를 매기고 모형별 DP를 계산했다. 음분포 기준의 프로파일은 Krumhansl–Kessler 장·단조 프로파일을 사용했다. Python 3.12.14, NumPy 2.3.5, Node 24.22.1에서 재현했다. [공식 내보내기](export_catalog.cjs) · [평가 코드](benchmark.py) · [프로파일 참고](https://github.com/cuthbertLab/music21/blob/86a7dc8a5fb3b1996ac0202d6bb9b4b9d19197/music21/analysis/discrete.py#L344).

저장소 루트에서 실행한다. ABC 원본은 지정한 연구 캐시에서 읽는다. 해시는 `source-manifest.json`과 비교한다.

```sh
research=docs/research/tab-harmony-automation
cache=/tmp/modus-abc
python "$research/fetch_abc.py" "$cache" dev
python "$research/fetch_abc.py" "$cache" calibration
python "$research/benchmark.py" "$cache" dev /tmp/modus-dev.json
python "$research/benchmark.py" "$cache" calibration /tmp/modus-calibration.json --lock /tmp/modus-key-lock.json
python "$research/fetch_abc.py" "$cache" test
python "$research/benchmark.py" "$cache" test /tmp/modus-test.json --lock /tmp/modus-key-lock.json
python "$research/controls.py" /tmp/modus-controls.json
node --import tsx "$research/product_controls.cjs"
```
