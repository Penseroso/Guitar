# P5 — TAB Analysis 제품 고도화 계획

기준은 `feat/tab-timing-inspection`의 `44afc75`다. P5의 성공 기준은 사용자가 **어느 코드 구간의 어떤 원본 음표를 근거로 선율의 역할을 읽었는지** 악보에서 확인하고, 같은 흐름에서 필요한 문맥을 보완할 수 있는가다. 시간 정보가 없는 TAB도 제공 코드와 연결해 읽는 현재 경로를 유지한다.

## 1. 현재 지원 범위와 제품 진단

| 단계 | 검증된 계약 | 현재 화면에서의 한계 |
| --- | --- | --- |
| P0 · TAB 입력과 패턴 | 프렛 입력·ASCII 붙여넣기로 순서 기반 TAB을 편집한다. 현재 `Analyze`는 악보 전체의 음과 지원 패턴을 읽고 원본 위치에 주석을 배치한다. | 분석에 제공 코드가 반영되는 것으로 오해하기 쉽다. 내장 예제는 전체 분석 주석을 소개하며 제공 코드 읽기로 이어지는 경로는 없다. |
| P1–P2 · 표기와 점검 | 시작 위치, 음표별 길이, 문서 박자표, 쉼표와 주법 표기를 선택적으로 편집한다. `Check timing`은 구조와 입력 완전성을 읽고 원본 위치로 이동할 수 있다. | 실제 읽으려는 시점에 어떤 입력이 필요한지와 점검 결과가 다른 화면 영역에 있다. 길이 입력은 음표별 동작이다. |
| P3–P3.3 · 표기 시간 | `This bar`는 명시적 마디 내 구간을 관찰한다. `Across full bars`는 유효한 박자표를 가진 정규 마디 모델을 명시적으로 선택하고, 앞 마디에서 이어지는 구간도 포함한다. 완전성은 질의 시점의 원본 음표 모집단에 대한 명목 표기 시간 판정이다. | 악보, 현재 관찰 마디, 시점 목록이 각자 다른 초점을 가진다. 현재 악보 선택으로 해석 근거를 보여주려고 하면 선택에 묶인 관찰이 닫힐 수 있다. |
| P4 · 시점 화음 읽기 | 정규 마디 모델에서 완전한 시점의 관찰을 공용 화음 수식에 대조한다. 후보 선택 후에만 그 가정 아래의 설명을 보여준다. | `View written time → Across full bars → Chord readings → Formula alternatives`를 찾아야 한다. 후보와 제공 코드가 서로 다른 상태와 패널에 있다. |
| P4 후속 · 제공 진행·선율 | 사용자가 제공한 코드를 포지션 범위 또는 명시적 표기 시간에 연결한다. 제공 코드, 선택한 원본 음표, 선택적 키 참조로 구간 관계와 조건부 선율 역할을 보여준다. 시간 없이도 포지션 경로를 쓸 수 있다. | 포지션을 고르고 패널에서 코드를 넣은 후 `Read progression`을 연다. 키는 별도 Context에서 설정하고 선율은 다시 범위 적용 또는 목록 선택이 필요하다. 악보 위 제공 코드 라벨과 진행·선율 결과에서 해당 원본 근거를 바로 열 수 없다. |

전체 분석은 문서 순서를, 제공 코드는 이력에 포함되는 별도 문맥을, 시점 후보는 일시적인 가정을 사용한다. 문서 수정 후 전체 분석은 갱신이 필요하고 이력에는 제공 코드가 포함된다. 제공 코드 변경만으로 TAB 패턴을 다시 계산할 필요는 없다. 시간 배치의 전제가 바뀌거나 원본 위치가 사라졌을 때는 기존 검토 상태가 적용된다. 워크스페이스를 벗어나면 일부 상세·선율 선택이 초기화되고, 현재 문서 이력은 앱 세션에 남는다. ## 3. 단계별 제품 계약과 수용 기준

### P5.1 — 결과의 근거를 악보에서 찾기

- 진행의 코드 쌍, 선율의 역할·이동, 시점의 관찰 음표에서 원본으로 이동하는 동작을 제공한다. 포지션에 붙은 제공 코드도 악보에서 골라 같은 상세를 열 수 있게 한다. 근거는 원본 음표·포지션 ID와 코드 행 ID로 연결한다. 앞 마디에서 관찰된 음표는 소유 Bar·Position·String과 시점의 정확한 좌표를 함께 확인할 수 있게 한다. 표기 시간 구간은 검증된 원본 음표가 있을 때 해당 음표에 연결하고, 그 외에는 정확한 구간과 배치 모델을 상세에 표시한다. 균등 배치된 포지션 열에 시간 구간을 눈대중으로 투영하지 않는다.
- 읽기용 강조는 편집 대상·범위·관찰 마디·이력과 독립적으로 관리한다. 명시적 이동에서만 포커스와 스크롤을 옮긴다. 원본이 지워졌거나 관찰이 만료되면 이동을 중단하고 이유를 표시한다. 미확정 프렛·분수·IME를 기존 보호 경로에서 확인해 포커스 이탈 전 동작을 막는다. 돌아오는 대상이 남아 있으면 Escape로 해당 결과 제어점에 복귀한다.
- **수용 기준.** `B3→C4`에서 결과 동작 한 번으로 양쪽 원본을 식별하고 기존 범위·문서·관찰 시점·이력이 유지된다. 클릭·탭·키보드로 같은 근거에 접근한다. 반복 피치나 두 마디 걸침에서도 다른 음표로 이동하지 않는다. 원본 삭제·Undo/Redo 후에는 유효성을 다시 확인하고 이전 결과를 자동 복원하지 않는다. [기존 점검 이동과 복귀](../../src/components/guitar/scale/tab-analysis/TabScoreView.tsx#L147) · [원본·배치 계약](../../src/domain/tab/supplied-harmony.ts)

### P5.2 — 분석 진입과 시간 관찰을 같은 악보 흐름으로 묶기

- 악보 곁에서 **TAB 패턴 읽기**와 **내 코드로 선율 읽기**의 목적과 기준을 드러낸다. 레이아웃 대안은 결과를 항상 펴 두는 다중 패널과 필요할 때 여는 간략 상세를 비교한다. 모바일 악보 공간과 기존 조작 유지에 유리한 간략 상세를 기본안으로 삼는다. 키 참조가 필요하다는 결과에서 기존 키 설정에 바로 접근하게 한다. 키 지정은 선택적이며 명시적으로 이뤄진다.
- 기본 `This bar`와 모델 선택은 유지한다. 점검 결과가 없거나 미입력이라는 이유로 포지션 기반 분석을 막지 않는다. 시점 후보는 기존의 완전한 시점에서, 관찰된 원본과 모델을 함께 제시한 뒤 바로 열 수 있게 한다. `C6 / Am7`처럼 여럿이 맞으면 선택지를 보여주고, 가정 선택만으로 악보에 제공 코드를 쓰지 않는다. 후보·제공 코드·조건부 해석은 화면의 해당 위치에서 짧은 문구로 구분한다.
- **수용 기준.** 새 세션에서 무시간 TAB을 붙여넣고 박자표나 시간 메뉴를 거치지 않고 제공 코드 해석에 도달한다. 키 안내에서 설정 흐름을 열고 완료 또는 취소하면 원래 결과와 범위로 돌아온다. 완전한 시점에서는 기존 네 단계의 공개 경로에서 한 단계 이상 줄어든다. 부분 시점은 확인된 음표와 보류 이유를 표시한다. 390px 화면에서도 주요 읽기 동작을 실행하는 동안 열린 여러 영역을 왕복할 필요가 없다. ### P5.3 — 악보에서 이미 선택한 범위와 선율을 활용하기

P5.3의 구현 기준은 `feat/tab-timing-inspection`의 `7e76c5b`다. 악보에서 범위를 선택하면 곁에 코드 입력과 선율 읽기 동작을 제공한다. 기존 패널은 입력과 결과를 계속 담당한다.

| 순서 | 사용자 흐름 | 구현 계약 |
| --- | --- | --- |
| **1. 코드 입력** | 범위 선택 → `Add chord to selection` → 기존 코드 입력기의 Apply | 클릭 시 범위의 양끝 포지션 ID와 현재 악보를 잡고 입력기에 범위를 표시한다. 포지션 배치 초안은 열린 뒤 범위 선택이 달라져도 처음 범위를 참조한다. 시작·종료 분수를 쓰는 시간 배치는 기존 별도 경로를 사용한다. 시간 기반 진행을 읽고 있을 때도 새 포지션 초안의 배치 방식과 읽는 진행의 방식은 각각 유지한다. |
| **2. 단선율 읽기** | 범위 선택 → `Read selected melody` → 진행·선율 결과 | 모든 포지션에 음표가 정확히 하나 있고 쉼표가 없는 기존 조건을 공유한다. 원본 음표 ID를 한 번에 넘겨 현재 진행 읽기를 열고, 결과에 포커스를 둔다. 현재 명시된 포지션 또는 시간 배치 방식으로 읽고, 참조할 코드가 없으면 선택한 선율을 유지하며 코드 입력을 안내한다. |
| **3. 다성 선율 선택** | 범위 선택 → `Choose melody notes` → 악보에서 음표 선택 → `Read melody` | 범위에 있는 기존 음표만 고르는 임시 모드다. 포지션마다 최대 한 음을 고른다. 같은 포지션의 다른 음을 고르면 교체하고, 선택된 음을 다시 누르면 해제한다. `Read melody`에서만 기존 분석으로 ID를 전달한다. 취소하면 직전 읽기에 사용한 선율을 유지한다. |

#### 상태와 조작

- 코드 입력은 기존 `selectedChordPositions`, `prepareSuppliedChord`, `save-supplied-chord` 경로를 재사용한다. 초안에 배치 방식을 명시해 패널에서 읽고 있는 방식과 분리한다. 열 때 입력기의 제목과 고정 범위를 보여주고, 저장·취소 후 진입 버튼으로 포커스를 돌린다. 저장 직전 악보와 배치 유효성을 다시 확인한다. 겹침·끊어진 범위·오래된 초안은 기존 안내와 검토 흐름을 따른다. Apply 성공은 이력 한 건이며 입력 열기·취소와 선율 선택은 이력에 쌓이지 않는다. [범위 및 배치 검증](../../src/domain/tab/supplied-harmony.ts#L45) · [저장 및 Undo/Redo](../../src/features/tab-analysis/state.ts#L254)
- 다성 선택은 기존 악보 그리드에 표시한다. 동일 그리드에서 편집 위치, 선율 선택, P5.1 근거 강조를 각기 식별할 수 있어야 한다. 클릭·터치 또는 Enter/Space로 원본 음표를 고르고, 방향키는 선택 가능한 음표 간 포커스만 이동한다. Tab은 그리드 밖 제어점으로 이동하며, Escape와 화면의 Cancel은 선택을 취소하고 진입 버튼으로 돌아간다. 이 모드에서 사용된 프렛 키·삭제·삽입·붙여넣기·열 길게 누르기는 편집을 시작하지 않는다. 기존 목록을 대체 경로로 유지한다. - 진입 요청은 사용자 동작마다 한 번만 처리한다. 미확정 프렛·시작 분수·IME 조합, 기존 코드 초안이 있으면 해당 입력의 명시적 확정 또는 취소를 먼저 요구한다. 검사 시점은 포인터 기본 동작이나 키 활성화보다 앞선다. 기존 편집기의 Enter/Tab/Escape 및 Set start 동작을 유지한다. 문서 교체, 대상 삭제 또는 Undo/Redo로 선택 근거가 바뀌면 임시 선택을 종료하고 안전한 활성 제어점으로 복귀한다. 읽기 선택과 근거 표시 사이를 전환할 때도 편집 대상·범위·written-time 관찰 위치를 보존한다. ## 4. 검증

관찰과 해석은 각각 따로 확인한다. 원본 위치·실제 저장된 기호·명시적 시간 구간은 관찰이다. 제공 코드는 사용자 문맥이며, 키 참조는 사용자가 지정한 기준이다. 화음 수식 일치, 로마 숫자, 선율 역할은 화면에 보인 문맥이나 가정 아래의 결과다. 완전한 표기 시점은 sounding·침묵·반주·조성의 완전성을 증명하지 않는다. 인접 코드나 순서가 불명확한 입력에서는 기존의 보류 규칙을 유지한다.

| 위험 | 최소 사례와 확인 |
| --- | --- |
| 근거 귀속 및 해석 | 무시간 `G7→C`, `B3→C4`에서 제공 코드·C장조 참조·두 원본 음표 확인. 같은 피치가 다른 줄과 포지션에 중복된 사례, 동시 시작 다성·쉼표 반례 포함. |
| 시간 경계 및 중의성 | 불완전한 `C/E/G/A`에서 관찰된 음과 보류 상태를 분리. 완전 시점에서 `C6 / Am7` 확인과 무기본 선택. 정규 마디 경계의 `[start,end)`와 carry-in 소유권, 박자표 제거, `This bar` 기본값 확인. |
| 상태 및 입력 보호 | 프렛·시작 분수·한글 IME 조합 중 포인터·탭·Enter/Space로 근거 보기 시도. Enter/Tab/Escape 및 Set start 기존 동작, 줄/위치/마디 삭제 이후의 안전한 포커스 복귀, Undo/Redo와 배치 검토 확인. 합성 조합 이벤트와 실제 한글 IME 입력의 역할을 구분한다. |
| 발견 가능성 | 브라우저 390/768/1335px에서 결과와 악보의 왕복 동작 수, 결과가 악보를 화면 밖으로 미는지, 44px·키보드 포커스·축소 모션 확인. 첫 사용자가 도움 없이 제공 코드와 가정, 이동의 원본 음표를 각각 설명할 수 있는지 과업 관찰. |
| 성능 및 회귀 | 기존 TAB 도메인·워크스페이스·타이밍·제공 코드 이력 테스트와 빌드 실행. 긴 다성 TAB 한 건에서 근거 강조, 상세 공개, 시점 이동 전후를 비교한다. UI용 선택이 도메인 분석 전체를 매번 재계산하거나 모든 상세를 동시에 렌더링하면 범위를 줄인다. |

## 5. 판정

**P5.1–P5.2 GO.** 기존 도메인 결과와 원본을 연결한 뒤 실제 사용자 과업에서 진입 경로를 줄인다. 위 수용 기준으로 연결·포커스·시간 의미의 회귀가 해소된 다음 P5.3의 악보 문맥 단축을 진행한다. 다성 선택의 편집 충돌이 남아 있으면 해당 단축은 보류한다.

**자동 코드 구간화·국소 조성·전조·sounding 추론은 P5 NO-GO.** 오프라인 연구에서 한 성부 자동 구간화는 고정 마디 기준선을 넘지 못했다. 전문가 코드가 주어지면 국소 조성 후보의 가능성이 높아졌으나, 연구 대상은 사중주였다. 연구용 외부 런타임, 기타 악곡 검증용 코퍼스, 못갖춘마디·변박, 일괄 입력과 프로젝트 저장·내보내기는 후속이다. [오프라인 연구와 판정](../research/tab-harmony-automation/README.md) · [UI 수용 원칙](../design-language.md)
